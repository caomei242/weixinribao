## 一句话结论

当前 V1 已经有“防漏收件箱”的骨架，但还不是用户每天能顺手用的工作台。主要问题不是缺几个按钮，而是主流程、状态、人话文案、候选池、客户打标和转述输出没有合成一个闭环。

目标闭环应是：

```text
抓没抓 -> 看 50 条 -> 谁说的 -> 抽了啥 -> 为啥抽 -> 确认 / 驳回 / 改类型 -> 自动带客户标签 -> 草稿日报 -> 转述摘要 -> 今日收口
```

## P0：不改不能实战

### P0-1 统一主流程为固定页切换

问题：

- 当前一会儿弹窗，一会儿跳到页面下方，一会儿三栏内滚动，用户容易迷路。
- 刷新后弹窗消失，主流程位置不保留。

返工要求：

- 左侧导航固定，顶部状态固定，中间主工作区随导航切换。
- `今日防漏 / 试读消息 / 候选收件箱 / 群客户打标 / 草稿日报 / 转述摘要 / 配置中心` 都是固定页，不使用主流程弹窗，不自动滚到页面下方。
- 刷新后恢复当前页、筛选、数据源和关键选择。

验收标准：

- 用户点 `转述摘要` 后刷新，仍在转述摘要页。
- 用户点 `配置中心` 后不出现弹窗，而是在固定工作区显示。
- 页面不再出现“点了按钮后跳到半截位置”的体验。

### P0-2 顶部状态改成人话工作状态

问题：

- 顶部现在像开发日志，用户看不懂有没有自动抓、上次抓没抓成、下次是否会抓。
- `failed`、`real_read_disabled`、`50 条`、`3 条` 混在一起，用户不知道到底失败还是成功。

返工要求：

- 首页顶部拆成状态卡：`服务健康`、`真实读取`、`最近一次可用结果`、`候选事项`、`草稿日报`、`今日收口`。
- 明确显示：自动抓取开关、抓取频率、上次成功抓取、下次计划抓取、本次失败原因。
- 技术字段放进 `诊断详情`，默认折叠。

验收标准：

- 用户不用看 error_code，也能知道：现在是否自动抓、最近可用结果是多少、下一步该点什么。
- 如果只是 30 分钟健康检查，页面必须明确写：`健康检查每 30 分钟；消息不会自动抓取。`

### P0-3 候选收件箱必须能处理，不只是能看

问题：

- 用户看不到为什么抽候选、类型是什么、能不能改、怎么确认或驳回。
- 右侧混着发送人识别和群档案，候选详情主操作不在视野内。

返工要求：

- 每张候选卡直接显示中文类型：`需求 / Bug / 咨询 / 结论 / 待跟进`。
- 候选详情固定结构：摘要、类型、为什么抽它、证据链、确认/驳回/改类型/补充说明。
- 底部固定操作条，不随滚动消失。

验收标准：

- 任意点击一条候选，用户 3 秒内能找到 `确认`、`驳回`、`改类型`。
- 用户能看到 1-2 句人话抽取理由。
- 确认后显示影响：是否进入草稿日报和转述摘要。

### P0-4 草稿日报接上最近试读候选

问题：

- 最近真实试读里有 3 条候选，草稿日报却读 `workspace` 后显示 0 条。
- 用户看到的是空草稿，无法完成日报闭环。

返工要求：

- 草稿日报默认识别当前可见候选，不要默认切到空池子。
- 当最近试读有候选而今日处理区为空时，主动提示：`发现最近试读 3 条候选，可生成试读草稿`。
- 数据源文案改成：`最近试读候选` / `今日已确认候选`，不用 `workspace`。

验收标准：

- 用户能用最近试读的 3 条候选一键生成草稿。
- 草稿日报前台显示生成时间、数据源、候选数、风险数、正文预览。

## P1：强烈影响使用

### P1-1 统一候选池口径

问题：

- `最近真实试读`、`当前工作台`、`workspace`、`recent50` 是内部概念，用户不该理解。

返工要求：

- 产品上只暴露一个 `候选收件箱`。
- 每条候选显示来源和状态：`来自最近试读`、`今日处理`、`已确认`、`已进草稿`。
- 如果需要导入，按钮改成：`把这 3 条加入今日处理`。

验收标准：

- 用户不需要切换池子，也能看到所有待处理候选。
- 草稿日报和转述摘要默认使用同一个用户可见候选列表。

### P1-2 试读消息要让用户确认看到完整 50 条

问题：

- 左侧只露出几条消息，用户不知道是不是完整 50 条。

返工要求：

- 试读消息区显示 `共 50 条，当前显示 1-50` 或明确的滚动 / 加载进度。
- 增加时间排序、发送人筛选、风险筛选、未关联候选筛选、关键词搜索。

验收标准：

- 用户能确认本次确实有 50 条原始消息。
- 用户能按发送人或关键词快速定位消息。

### P1-3 发送人识别和我方人员库全局生效

问题：

- 保存某人为我方后，前台仍显示旧身份。
- 我方人员不该每个群、每次重复配置。

返工要求：

- 建立全局 `我方人员库`，保存一次后所有群、消息、候选、草稿、转述统一生效。
- 保存发送人映射后即时刷新所有相关展示。
- 支持从草莓客户管理系统关系人库读取内部支持 / 我方候选人员，用户只确认。

验收标准：

- 用户把某发送人标为 `我方` 后，消息卡、发送人列表、候选详情、草稿日报都同步。
- 保存反馈写明：`已标为我方，影响 X 条消息，可撤销。`

### P1-4 群 / 客户打标自动匹配草莓客户管理系统

问题：

- 用户不想从零手填客户标签；草莓客户管理系统已经有客户页、客户总表、项目页、关系人库。

返工要求：

- 增加 `从草莓客户管理系统匹配` 主按钮。
- 按群名、会话名、发送人昵称、客户关键词只读匹配客户页 / 客户总表 / 项目页 / 关系人库。
- 匹配结果以候选方式展示：推荐客户、匹配依据、置信度、一键套用。
- `群负责人` 拆成 `客户主联系人` 和 `我方跟进人`。

验收标准：

- 用户无需手填，也能一键套用客户名称、业务模块、客户阶段、群类型、常用联系人、回复注意事项。
- 微信后台修正只写本项目本地配置，不反向修改草莓客户管理系统。

### P1-5 转述摘要改成用户任务，不是导出中心

问题：

- 页面按模板、数据源、导出参数组织，用户不知道发给谁、怎么用。

返工要求：

- 转述摘要固定页改为三个任务入口：`给客户回复`、`给内部产品 / 技术同步`、`给自己留今日复盘`。
- 每个入口说明适合发给谁、包含什么、不会包含什么。
- 预览默认是可直接复制的人话版本。
- 按钮改成：`复制摘要`、`下载 Markdown`、`保存本地`。

验收标准：

- 用户不需要理解模板名，也能选择正确转述场景。
- 复制出来的摘要不含技术字段、真实敏感原文、wxid、key、salt、DB 路径或 daemon 日志。

### P1-6 全局文案改成用户语言

问题：

- 大量文案像给开发 / 审查员看的，不像给每天处理反馈的人看的。

返工要求：

- 建立文案映射：
  - `workspace` -> `今日处理区`
  - `real_trial` -> `最近试读`
  - `pending` -> `待确认`
  - `resolved` -> `已识别`
  - `local_review` -> `本机待审`
  - `real_read_disabled` -> `真实读取未开启`
  - `正式区写入禁用` -> `不会自动写入正式日报`
  - `本地 Markdown` -> `已生成本机草稿`
- 技术说明放入 `诊断详情` / `安全说明`，默认折叠。

验收标准：

- 主流程页面不出现 `workspace`、`real_trial`、`binary`、`formal_write` 等开发词。
- 空状态都告诉用户下一步。

## P2：体验优化

### P2-1 今日防漏收口清单

返工要求：

- 首页增加一张 `今日收口` 清单：
  - `已试读 50 条`
  - `待确认候选 3 条`
  - `已确认 0 条`
  - `草稿日报未生成`
  - `转述摘要未复制`
- 每项右侧给主按钮。

验收标准：

- 首页能直接说：`今天还没收口：还有 3 条候选没确认，草稿日报未生成。`

### P2-2 写操作统一反馈和撤销

返工要求：

- 所有保存 / 确认 / 驳回 / 改类型 / 导出动作统一反馈：动作成功、影响范围、下一步、撤销入口。
- 增加轻量操作历史。

验收标准：

- 用户能看到刚刚做了什么、影响几条、能否撤销。

### P2-3 敏感信息默认隐藏

返工要求：

- wxid、key、salt、真实 DB 路径、daemon 日志、技术错误栈默认不在主流程展示。
- 需要排障时进入 `诊断详情`。

验收标准：

- 草稿日报、转述摘要、走查记录、状态卡和回报队列不包含敏感技术标识。

## 建议原型

```text
┌────────────────────────────────────────────────────────────┐
│ 微信反馈防漏收件箱 V1                                      │
│ 服务健康 正常｜真实读取 关闭｜最近结果 50条/3候选｜今日未收口 │
├──────────────┬─────────────────────────────────────────────┤
│ 今日防漏      │ 今日还差：3 条候选未确认，草稿日报未生成       │
│ 试读消息      │ [查看 50 条消息] [处理 3 条候选] [生成草稿]     │
│ 候选收件箱    │                                             │
│ 群客户打标    │ 固定工作区：随左侧导航切换，不弹窗、不跳下方    │
│ 草稿日报      │                                             │
│ 转述摘要      │                                             │
│ 配置中心      │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

候选详情页：

```text
候选：客户反馈了一个待处理问题
类型：Bug / 需求 / 咨询 / 结论 / 待跟进
为什么抽它：出现明确问题描述，且没有看到闭环回复
证据链：关联 3 条原始消息 [跳到原文]
发送人：已识别为客户方，可改

[确认进入草稿] [驳回] [改类型] [补充说明] [撤销]
```

转述摘要页：

```text
你要发给谁？
[给客户回复] [给内部产品/技术同步] [给自己留今日复盘]

数据：今日候选 3 条，已确认 0 条，待确认 3 条
预览：人话摘要，可直接复制

[复制摘要] [下载 Markdown] [保存本地]
```

## 不做事项

- 不要求本轮接入多群全量自动化。
- 不要求自动外发客户消息。
- 不要求直接写正式日报、正式待办池或 Obsidian 正式区。
- 不要求反向修改草莓客户管理系统真实客户资料。
- 不把真实消息正文、候选正文、wxid、key、salt、DB 路径或 daemon 日志写入返工包。
