## 主要问题

1. 最近真实试读候选没有进入人工确认 / 导出闭环。
   - 当前页面已经能告诉用户“最近试读有候选”，但候选仍在独立试读产物中。
   - 用户切到最近真实试读后只能看摘要，不能确认、驳回、补负责人、改优先级，也不能直接用于三类 Markdown 模板。
   - 产品影响：实战测试会卡在“看到了候选，但不能把它变成日报 / 待办”。

2. 试读日期范围没有按用户明确要求落地。
   - 需求要求起始日期时间、结束日期时间、最近条数，并支持“最近2小时 / 今天 / 最近50条”。
   - 当前实现只有最近条数和回看小时，快捷项没有把起止日期时间可视化。
   - 产品影响：用户无法明确知道“这次到底读哪一天、哪一段时间”。

3. 导出模板和最近试读候选的数据源割裂。
   - 脱敏接口显示最近试读有候选，但 `product_tech_summary` 预览元数据当前 `item_count=0`，原因是模板读主工作台候选池。
   - 产品影响：用户点击导出模板时会以为抽取失败或导出坏了。

4. 新旧导出入口并存，可能误导用户。
   - 顶部同时有 `导出模板`、`导出日报`、`导出待办`。
   - 新模板是本轮主路径，旧按钮仍会让用户困惑“该点哪个才是新日报”。

## 返工验收标准

- 配置中心试读条件必须出现起始日期时间、结束日期时间、最近条数；快捷项会同步更新这些字段。
- 无范围、白名单为空、白名单不唯一时，真实试读仍必须阻断。
- 当主工作台候选为 0、最近真实试读候选大于 0 时，页面必须给出明确操作：
  - `把本次试读候选加入待确认`，或
  - `导出模板数据源：当前工作台 / 最近真实试读`。
- 如果选择导入主工作台，必须只做本地候选导入，不读取新消息、不外发、不写正式区，并保留人工确认状态。
- 如果选择导出最近真实试读，Markdown 预览的候选数量必须与所选数据源一致，并继续遵守审阅版 / 待办版 / 转发版安全边界。
- 最近真实试读候选进入确认前，不得展示原文证据；进入本地确认流后，证据展示仍必须只限本地页面，不写状态卡 / 回报队列 / 产品走查文档。
- 顶部旧导出按钮需弱化、改名或提示推荐使用 `导出模板`，避免用户走错路径。
- 默认 `real_read_enabled=false` 不得被保存为开启；正式写入仍保持禁用。
