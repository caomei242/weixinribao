# 微信反馈防漏收件箱 V1 P1 候选池、文案与客户打标复验

时间：2026-05-18 17:12 CST

## 结论

P0 展示形态之外，当前还有三类会明显影响实战使用的问题：

- 候选池口径仍暴露内部概念。
- 页面文案仍混入大量开发 / 审查语言。
- 群 / 客户打标仍主要靠手填，未复用草莓客户管理系统。

这些不一定阻塞第一轮结构返工，但如果不做，用户即使看到页面，也仍然会不知道该处理哪个池子、日报里为什么是未标对象、转述摘要能不能直接复制。

## 问题一：候选收件箱默认空池

实际表现：

- 进入候选收件箱后，存在 `当前工作台` 和 `最近真实试读` 两个来源切换。
- 当来源为 `当前工作台` 时，候选数为 0。
- 切到 `最近真实试读` 后，候选数为 3。
- 空状态仍提示用户去切另一个来源。

产品判断：

- 用户不应该理解 `当前工作台`、`最近真实试读` 两个候选池。
- 对用户来说只有一个概念：`候选收件箱`。
- 来源应该是候选条目上的标签，例如 `来自最近试读 / 已加入今日处理 / 已确认 / 已进草稿`，不是让用户先选池子。

返工要求：

- 候选收件箱默认展示当前最该处理的候选。
- 如果今日处理区为空但最近试读有 3 条候选，默认直接显示这 3 条，并提示 `先确认这 3 条候选`。
- `加入待确认` 可以保留为状态动作，但不能成为看到候选的前置门槛。
- 去掉主流程中的 `当前工作台 / 最近真实试读` 二选一；内部数据源只放在诊断详情或候选来源标签。

验收标准：

- 用户点击 `候选收件箱`，能直接看到 3 条待确认候选。
- 用户不需要先点 `最近真实试读`。
- 空状态只在确实没有任何候选时出现，并告诉用户下一步。

## 问题二：文案仍像后台 / 审查工具

实测仍可见的用户不友好词：

- `real_read_disabled`
- `tech / ops`
- `resolved`
- `本地 Markdown`
- `正式区`
- `导出`
- `未标对象`
- `审阅版`
- `待办池`

产品判断：

- 这些词对开发和安全审查有意义，但不适合放在用户主流程。
- 用户想知道的是：有没有抓到、谁说了什么、这条该不该管、给谁处理、能不能复制给别人。

返工要求：

- 建立用户语言映射：
  - `real_read_disabled` -> `真实读取未开启`
  - `tech` -> `技术处理`
  - `ops` -> `运营处理`
  - `resolved` -> `已识别`
  - `pending` -> `待确认`
  - `none` -> `无风险`
  - `本地 Markdown` -> `本机草稿`
  - `正式区` -> `正式日报 / 正式待办`
  - `导出` -> `生成 / 复制摘要`
  - `未标对象` -> `待确认客户`
- 主流程页面不直接展示内部字段值。
- 技术状态统一进 `诊断详情`。

验收标准：

- 一级页面和主要卡片不出现 `workspace / real_trial / pending / none / tech / ops / resolved / real_read_disabled / formal_write`。
- 转述摘要默认是可复制的人话结果，不是 Markdown 导出配置页。
- 草稿日报默认写给用户审阅，不使用后台状态词堆字段。

## 问题三：客户打标字段有，但没有自动匹配

实际表现：

- 页面能显示 V1 字段：客户名称、群负责人、业务模块、客户阶段、群类型、常用联系人、回复注意事项。
- 当前仅客户名称和业务模块有值，其余大量显示未配置。
- 草稿日报 / 转述摘要里仍出现 `未标对象`。
- 未看到从草莓客户管理系统自动只读匹配、推荐套用或人工确认的流程。

产品判断：

- 字段覆盖不等于打标好用。
- 用户已经说不想自己手动打标，客户信息应该从草莓客户管理系统带出来，人工只确认。
- 如果客户打标不进日报和转述摘要，后面仍然要用户自己改文案。

返工要求：

- 只读接入草莓客户管理系统客户资料，不反向修改客户系统。
- 按群名、客户名、常用联系人、别名做匹配推荐。
- 在群 / 客户打标页展示：
  - `匹配到的客户`
  - `置信度 / 匹配依据`
  - `可套用字段`
  - `仍缺字段`
  - `确认套用到本地配置`
- 套用后同步影响候选收件箱、草稿日报和转述摘要。

验收标准：

- 用户不需要从零手填客户名称、阶段、群类型、联系人和回复注意事项。
- 转述摘要里不再默认出现 `未标对象`。
- 只读匹配失败时，页面明确写 `未匹配到客户，请手动选择或新增本地映射`。

## 建议优先级

- P1-1：候选收件箱统一候选池，默认显示最近可处理候选。
- P1-2：主流程文案改成人话，开发词只进诊断。
- P1-3：群 / 客户打标只读匹配草莓客户管理系统，并同步到草稿和转述。

## 不做事项

- 不开启真实自动读取。
- 不写正式日报 / 正式待办池。
- 不修改草莓客户管理系统真实资料。
- 不在走查文档、状态卡或监工回报里摘录真实消息正文。
