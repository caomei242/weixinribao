# 最近50条真实样本产品优化

- 任务标记：`监工派工：2026-05-18 11:06｜产品优化｜最近50条真实样本候选规则与前台需求优化`
- 线程：微信agent专项 产品助手
- 写入时间：2026-05-18 11:07 CST
- 产品边界：本轮只做产品判断、需求优化和文档沉淀；不改业务代码，不派开发，不写真实业务数据。

## 本轮依据

- 使用材料：开发助手状态卡、测试审查助手状态卡、README 中的真实读取安全口径、既有开发需求收件箱。
- 使用统计：raw 读取 50、raw 入库 50、去重 0、candidate 3、risk_candidate 0。
- 安全前提：默认 `real_read_enabled=false` 未变；真实读取仅在本轮授权下运行时开启；本轮为单一白名单会话最近 50 条窄范围试点。
- 未使用内容：未打开真实 SQLite，未打开真实导出正文，未查询或摘录真实消息正文、真实会话列表、wxid、key、salt、真实 DB 路径或 daemon 原始日志。

## 产品结论

当前能力可以算“人工辅助试用可用”，还不能算“无人值守日报可用”。

可用点：

- 真实读取链路已经跑通：能在授权范围内完成读取、入库、候选生成和本地导出。
- 安全边界可接受：默认真实读取关闭，运行时开启未沉淀成默认配置，测试审查未发现越界读取或外发。
- 候选抽取已经有真实触发：50 条里生成 3 条候选，说明规则不是纯空转，能从真实群消息中抓到一部分需要人工审阅的事项。

不足点：

- 3/50 只能说明规则偏保守或样本中有效反馈较少，不能证明召回率足够。
- risk_candidate 为 0 不能直接解释为没有风险内容，也可能是当前风险关键词和规则覆盖不足。
- 前台目前更像“开发调试工作台”，还缺一个用户可安全点击的“单会话最近50条试读”入口和读后复盘面板。
- 候选质量还缺人工反馈字段，无法沉淀“哪些候选是真反馈、哪些是误提、哪些漏提”。

## 前台产品优化建议

### 1. 增加“单会话最近50条试读”入口

入口位置建议放在工作台顶部状态条右侧，和普通“立即采集”区分开。

```text
┌──────────────────────────────────────────────────────────────┐
│ 模式：real | 默认真实读取：关闭 | 试读范围：单一白名单 / 50条 │
│ wx-cli：ok | 会话白名单：1 | 上次试读：success               │
│ [测试连接] [试读最近50条] [查看安全说明]                     │
└──────────────────────────────────────────────────────────────┘
```

点击 `试读最近50条` 后必须出现确认弹窗，但文案要短，不要让用户读一大篇：

```text
本次只读试点

范围：单一白名单会话，最近 50 条
不会：修改默认配置 / 外发原文 / 自动回复 / 写正式待办池
结果：进入本地候选列表，需人工确认

[取消] [开始只读试读]
```

### 2. 安全状态必须前台可见

前台至少显示这些脱敏状态：

- 当前模式：fixture / real。
- 默认真实读取开关：关闭 / 开启。
- 本次是否运行时开启：是 / 否。
- 白名单会话数量：必须为 1。
- 读取限制：最近 50 条，或当前授权范围。
- 最近一次结果：success / failed / blocked。
- 失败原因：使用错误码和下一步建议，不显示原始日志。

### 3. 读后结果页先显示统计，再进入候选确认

试读完成后不要直接把用户丢进长列表，先给结果摘要：

```text
试读结果

读取：50  入库：50  重复：0
候选：3   风险候选：0
状态：仅本地保存，未写正式日报 / 待办池

[查看候选事项] [导出本地 Markdown] [重新试读]
```

### 4. 候选列表增加“规则解释 + 人工反馈”

候选卡片建议展示：

- 事项类型：需求 / bug / 咨询 / 沟通结论 / 待跟进。
- 脱敏摘要：只展示本地生成摘要，不进入状态卡或回报队列。
- 触发原因：例如命中需求词、疑问句、跟进词、异常词。
- 置信度：高 / 中 / 低。
- 操作：确认、驳回、改类型、标风险、负责人、优先级、下游同步对象。
- 反馈：误提、类型错、漏风险、需要补规则。

## 候选规则优化建议

candidate=3 的产品含义：

- 这是一个健康的早期信号：规则能产出候选，且没有把 50 条全打成候选，噪声暂时可控。
- 这不是成熟信号：样本只有 50 条，没有候选正文质量标注，不能判断 3 条是否都对，也不能判断漏掉多少。
- risk_candidate=0 需要谨慎：它可以代表样本中没有风险，也可以代表风险规则偏窄。

下一步优先级：

1. 先调交互：补“试读结果摘要 + 候选人工反馈”，让用户能快速判断 3 条是否有价值。
2. 再调规则：基于人工反馈调整需求词、问题词、咨询词、跟进词、风险词和重复合并口径。
3. 再补样本：继续只使用用户另行授权的单会话小样本，不默认扩大范围。

建议新增规则反馈字段：

- `review_result`：有效 / 误提 / 漏提补录。
- `correct_type`：人工修正后的事项类型。
- `risk_override`：人工标记风险 / 取消风险。
- `rule_feedback`：短备注，例如“太宽”“太窄”“应归为咨询”。
- `trigger_reason`：系统记录规则触发原因，便于回溯。

不建议本轮做的事：

- 不因为 candidate 只有 3 就直接扩大读取范围。
- 不引入外部 LLM 读客户原文。
- 不自动把候选写正式待办池。
- 不把真实原文放进状态卡、回报队列或产品走查文档。

## 是否需要新增 / 调整开发需求

需要新增 1 条开发需求：`真实试读前台安全入口与候选反馈闭环`。

需求性质：

- 优先级：高于继续扩大真实读取范围。
- 目标：让用户能安全地在前台发起单会话最近 50 条试读，并把 candidate=3 这类结果转化为可评价、可调参的人工反馈。
- 边界：不改变默认 `real_read_enabled=false`，不扩大读取范围，不写正式待办池。

## 剩余风险

- 当前只有脱敏统计，没有候选质量标签；候选抽取准确率和召回率仍未知。
- 最近 50 条是不限定 2 小时的授权例外，不应沉淀为默认产品行为。

- 真实试点产物包含真实内容，后续所有产品 / 测试 / 监工文档仍应只记录统计和判断，不摘录正文。
